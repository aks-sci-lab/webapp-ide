# 웹앱제작기

레이아웃을 그리고 → **3대 세션(🧭 통합 개발 세션 · 🧩 영역별 병렬 세션 · 🧪 검증 세션)**으로 AI 웹앱을 설계·구현·자동 검증하는 로컬 웹앱 디자이너 및 통합 개발 환경.

## 실행

```bash
npm install
npm start
npm test          # 핵심 엔진 + E2E 바이브 코딩 시뮬레이션 테스트
npm run verify-app # 만든 웹앱을 헤드리스 브라우저로 통합 검증
```

또는 `웹앱제작기 실행.bat`을 더블클릭해 실행합니다.
브라우저에서 http://localhost:5180 접속 → ⚙️ 설정에서 AI 제공자와 **세션별 전용 모델**을 고릅니다.

| 제공자 | 준비물 |
|---|---|
| Google Gemini | API 키 (aistudio.google.com) → "모델 불러오기"로 모델 선택. `GEMINI_API_KEY` 환경변수 지원. 503 혼잡 시 자동 재시도·폴백 |
| Anthropic Claude | API 키 (platform.claude.com). `ANTHROPIC_API_KEY` 환경변수 지원 |
| OpenAI 호환 / 로컬 LLM | OpenAI(`https://api.openai.com/v1`), OpenRouter(`https://openrouter.ai/api/v1`) + API 키(`OPENAI_API_KEY`) 또는 LM Studio(`http://localhost:1234/v1`) / Ollama(`http://localhost:11434/v1`) |

## 3대 세션 개발 방식

우측 패널 상단의 세션 스위처로 역할을 분리해 개발합니다:
1. **🧭 통합 개발 세션**: 앱 전체 구조·레이아웃·공통 디자인 토큰·이벤트 규약을 설계하고, **⚡ 영역 병렬 실행**으로 여러 영역 세션을 동시에 실행합니다.
2. **🧩 레이아웃 영역별 세션**: 각 영역(`regions/<id>/`)이 독립된 세션과 코드 3종(`view.html`, `style.css`, `script.js`)을 가집니다. **🎯 요소 선택(Inspect-to-Edit)**과 **🖼 참고 이미지 첨부(Ctrl+V·드래그)**로 정밀하게 수정합니다.
3. **🧪 검증 세션**: 문법·중복 ID·영역 연결·실제 브라우저 런타임·시나리오 테스트(`tests.json`)를 통합 검증하고, **⚡ 기본 테스트 자동 생성 / 🤖 AI 테스트 생성** 및 **🩺 실패 영역 자동 수정 루프(Auto-Heal)**를 실행합니다.

로컬 모델이 규칙을 어기고 `@scope` / `(function (root, app) {...})` 래퍼를 직접 써도 저장할 때 자동으로 벗겨냅니다.

## 사용 흐름

1. **레이아웃**: 캔버스 빈 칸을 드래그해서 영역 생성. 끌어서 이동, 오른쪽 아래 모서리로 크기 조절. 상단에서 열/행/간격, "화면 채우기"(앱형/페이지형) 설정.
2. **이름 + 프롬프트**: 오른쪽 패널에서 이름, ID(=폴더 이름), 구현할 내용을 적고 **⚡ 바이브 코딩** (Ctrl+Enter). 기존 코드가 있으면 그 위에서 수정합니다.
3. **📝 앱 설명**: 앱 전체 목적/분위기 — 모든 영역 생성 시 함께 전달.
4. **분할 / 미리보기**: 조립된 앱을 바로 확인. `📦 내보내기` → `project/dist/index.html` 단일 파일.

## 로그 (문제 분석용)

IDE 를 쓰는 동안 일어난 일이 `webapp-ide/logs/<날짜>/` 에 남습니다. 상단 **📜 로그** 에서 날짜·종류별로 볼 수 있습니다.

- `events.jsonl` — 한 줄에 하나씩:
  - **변경**: 영역 파일·공통 파일 저장(크기, 바뀐 줄 수, 이전 버전 백업 위치), 레이아웃 변경(추가·삭제·이동한 영역, 그리드·모드), 영역 삭제·이름 변경·되돌리기
  - **AI 호출**: 용도(region / plan / plan-layout-fix / shared-css / describe), 제공자·모델, 소요 시간, 토큰, 오류, 원문 파일 위치
  - **AI 결과**: 저장됨(ai-saved) / 저장 거부(ai-rejected, 예: 앱이 쓰는 id 삭제)
  - **계획**: 프로젝트 요청, 단계, 배치 검사 결과 · 실행 결과(plan-run)
  - **요청**: 바꾸는 API 요청과 실패한 요청(경로, 상태, 시간, 본문 요약, 오류)
  - **브라우저**: 미리보기 스크립트 오류(어느 영역인지), 편집기 오류, 오류 알림
- `ai/<시각>-<용도>-<영역>.md` — AI 에게 보낸 system·prompt 와 받은 응답 원문 전체
- API 키·토큰 같은 비밀값은 `[숨김]` 으로 바뀌어 기록되지 않습니다.
- ⚙️ 설정에서 끄거나 보관 기간(기본 30일)을 바꿀 수 있습니다. 문제를 물어볼 때 해당 날짜 폴더를 그대로 전달하면 됩니다.

## 프로젝트 전체 프롬프트

영역을 선택하지 않으면(상단 **🧭 프로젝트**, Esc, 빈 곳 클릭) 오른쪽에 프로젝트 패널이 나옵니다.

- **요청**: 앱 전체에 대한 요청을 적고 **🧭 계획 세우기** (Ctrl+Enter) → AI 가 영역마다의 기능·프롬프트를 보고 요청을 영역별 작업 지시로 나눕니다.
  - 단계마다 대상 영역(또는 🎨 공통 CSS)과 지시가 보이고, 체크를 끄거나 지시를 직접 고칠 수 있습니다.
  - 지금 영역으로 안 되는 일은 "새 영역 제안"으로 알려 줍니다 (캔버스에 그린 뒤 다시 계획).
  - **▶ 실행** 하면 단계 순서대로 각 영역을 바이브 코딩합니다. 영역 AI 에게는 단계 지시와 함께 프로젝트 전체 요청이 전달됩니다.
  - **📐 레이아웃 재배치**: "좌우로 나눠", "2단으로" 같은 배치 요청이면 계획에 새 배치가 축소 그림으로 나옵니다. 실행하면 영역 코드는 그대로 두고
    IDE 레이아웃(영역 위치·크기)만 바꾸므로 캔버스에도 그대로 보입니다. 가져온 앱은 문서 흐름에서 그리드 앱으로 바뀝니다. "↩ 레이아웃 되돌리기"로 이전 배치로 돌아갑니다.
  - 대화상자만 담은 영역은 화면 칸을 차지하지 않는 "오버레이"로 캔버스 아래에 따로 표시됩니다.
  - 안전장치: 배치를 CSS(body/html/#app 의 grid·flex)로 바꾸려는 단계는 기본으로 꺼지고, 공통 CSS 에 그런 규칙이 들어오면 저장하지 않습니다.
    가져온 앱에서 AI 가 전역 스크립트(app.js)가 쓰는 요소의 id 를 지우면 그 영역은 저장하지 않습니다.
- **앱 설명**: 앱의 목적·분위기 등 늘 함께 전달되는 설명 (예전 "📝 앱 설명").
- **기록**: 프로젝트 요청과 계획 기록.
- 저장 위치: `project-prompt.md`(마지막 요청), `project-plan.json`(마지막 계획), `project-prompt-log.md`(기록). 공통 CSS 를 AI 가 고치기 전 `shared/.history/` 에 백업합니다.

## 기능 보기

영역을 선택하면 인스펙터의 **기능** 탭에 그 영역에 구현된 기능이 나옵니다. 기능 하나 = 영역 HTML 의 최상위 블록 하나
(감싸는 요소가 하나뿐이면 그 안쪽 블록들). 버튼·입력 개수와 호출하는 함수도 함께 보여 주고, 캔버스 상자에도 기능 이름이 칩으로 표시됩니다.

- 기능을 누르면 미리보기에서 해당 요소로 스크롤하고 깜빡여 위치를 보여 줍니다.
- **🤖 AI로 기능 설명** 을 누르면 AI 가 기능마다 이름과 한 줄 설명을 붙입니다 (`regions/<id>/features.json`, 블록 내용이 바뀌면 다시 설명).

## 분할 · 합치기 · 안쪽 레이아웃

- **나누기**: 영역을 고르고 인스펙터의 "레이아웃"에서 방향(좌우/상하)과 개수를 정해 **나누기** → 같은 레벨의 영역 여러 개가 됩니다.
- **안쪽으로 나누기**: 영역 안에 12×12 안쪽 레이아웃을 만들고 그 안에서 나눕니다.
- **기능 배치**: 기능이 2개 이상인 영역을 나누면 기능마다 보낼 조각과 조각 이름을 정하는 창이 뜹니다.
  - 안쪽으로 나누면 CSS·JS 는 바깥 영역에 남아 안쪽 조각 모두에 그대로 적용됩니다.
  - 같은 레벨로 나누면 CSS 는 내용을 받은 조각마다 복사되고, JS 는 원래 영역에 남아 `root` 가 모든 조각을 함께 가리킵니다 (layout.json 의 `jsRoots`).
- **안쪽 레이아웃 편집**: 영역을 더블클릭하거나 "안쪽 열기" → 캔버스가 그 영역 안을 보여 줍니다. 그 안에서 다시 그리기·나누기·합치기를 할 수 있고, 몇 단계든 중첩됩니다. 상단 경로(앱 › …)나 Esc 로 바깥으로 나갑니다. 상단의 열/행/간격은 지금 보고 있는 레벨에 적용됩니다.
- **합치기**: Shift(또는 Ctrl)+클릭으로 같은 레벨의 영역을 여러 개 고르고 **하나로 합치기**. 빈틈없는 직사각형이 될 때만 합쳐지고, 맨 위·왼쪽 영역의 ID 가 남으며 나머지의 HTML·CSS·JS 가 이어 붙습니다 (JS 는 `{ }` 블록으로 감싸 변수 충돌 방지).
- **안쪽 레이아웃 풀기**: 안쪽 영역들을 바깥 영역 하나로 다시 합칩니다.
- 안쪽 레이아웃이 있는 영역은 자기 HTML 대신 안쪽 그리드를 그리고, 자기 CSS·JS 는 그대로 적용됩니다. 영역 파일은 중첩과 상관없이 `regions/<id>/` 에 평평하게 저장됩니다.

## 기존 웹앱 가져오기

상단 **📥 가져오기** → HTML 파일 선택 → 새 프로젝트로 만들어집니다 (AI 호출 없음, 원본 그대로 동작).

- `<head>` 의 CDN·폰트 → `shared/head.html`, `<style>` → `shared/global.css`, 인라인 `<script>` → `shared/app.js`
- `<body>` 최상위 블록 → 영역 (연속된 `<dialog>` 는 한 영역). 레이아웃은 "문서 흐름" 모드로, 원래 순서대로 이어 붙습니다.
- 영역을 프롬프트로 고치면 AI 에게 그 영역 마크업이 참조하는 app.js 함수·코드가 함께 전달됩니다.
  기존 전역 함수는 영역 `script.js` 에서 `window.함수명 = ...` 으로 덮어써서 조금씩 영역 쪽으로 옮길 수 있습니다.
- 공통 파일(global.css / app.js / head.html)은 **🎨 공통 파일** 에서 직접 편집합니다.
- 브라우저 저장소(IndexedDB, localStorage)는 주소별로 따로라서, 원본 파일에서 쓰던 데이터는 IDE 미리보기에 보이지 않습니다.

## 파일 구조 (프로젝트 = `projects/<이름>/`, 영역 = 폴더 하나)

```
projects/<이름>/
  layout.json            그리드 + 영역 위치 (mode: grid | flow)
  shared/global.css      공통 스타일
  shared/head.html       CDN 라이브러리·폰트
  shared/app.js          전역 스크립트
  regions/<id>/
    prompt.md            마지막 프롬프트
    prompt-log.md        프롬프트 기록
    view.html            마크업
    style.css            @scope([data-region=id]) 로 자동 격리
    script.js            (root, app) 함수로 자동 감쌈
    .history/            덮어쓰기 전 자동 백업 (기록 탭에서 되돌리기)
  dist/index.html        내보내기 결과
```

영역끼리는 `app.emit('영역ID:동작', data)` / `app.on(...)`, 공유 상태는 `app.set/get` 으로 통신합니다.
`projects/<이름>/` 폴더는 Claude Code 로 직접 고쳐도 됩니다 (각 프로젝트의 `CLAUDE.md` 참고). 📋 프롬프트 복사 버튼으로 영역 컨텍스트 전체를 복사할 수 있습니다.

## 코드 구조

- `server.js` — API 라우트 (레이아웃, 영역 파일, 생성 스트리밍, 미리보기, 내보내기)
- `lib/project.js` — 파일 저장소 (폴더 생성/이름 변경/백업/휴지통)
- `lib/build.js` — 영역 파일들을 단일 HTML 로 조립
- `lib/importer.js` — 기존 HTML 을 영역·공통 파일로 분해
- `lib/layout-ops.js` — 나누기 / 합치기 / 안쪽 레이아웃 풀기
- `public/tree.js` — 레이아웃 트리 유틸 (서버·편집기 공용)
- `public/tokens.js` — 디자인 토큰(:root 변수) 읽기·쓰기
- `lib/logger.js` — 작업·AI 로그
- `lib/snapshots.js` — 프로젝트 전체 스냅샷
- `lib/validate.js` — AI 결과 저장 전 검사
- `lib/analysis.js` — 연결 지도, app.js 나누기 (acorn)
- `lib/offline.js` — 오프라인 내보내기
- `lib/ai.js` — 공통 프롬프트, 응답 파싱/정리, Claude 호출
- `lib/gemini.js` — Gemini REST 호출
- `lib/local.js` — 로컬 LLM (OpenAI 호환) 호출
- `public/` — 편집기 UI (빌드 과정 없는 바닐라 JS)
